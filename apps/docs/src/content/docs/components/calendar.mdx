A lightweight date / range picker. Markup and CSS are yours. The package fills
the grid and handles selection. `<cinq-calendar>` follows the
[WAI-ARIA Authoring Practices date picker grid](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/examples/datepicker-dialog/).

Inspired by [`@19h47/calendar`](https://github.com/19h47/19h47-calendar).

## Install

```bash
pnpm add @agencecinq/calendar
```

## Usage

Import once:

```js
import "@agencecinq/calendar";
```

Then write the grid markup. The host `<cinq-calendar>` fills weekday headers and
day cells, and wires selection + keyboard navigation.

> **HTML is the source of truth.** The component does not invent missing ARIA
> attributes. Provide `role="grid"`, labels, and live regions yourself, and
> `aria-multiselectable="true"` on the grid in `range` and `multiple` modes.

```html
<cinq-calendar locale="fr" deselect>
  <header>
    <button type="button" class="js-previous" aria-label="Previous month">Previous</button>
    <h2 class="js-title" id="calendar-label" aria-live="polite"></h2>
    <button type="button" class="js-next" aria-label="Next month">Next</button>
  </header>
  <table role="grid" aria-labelledby="calendar-label">
    <thead>
      <tr class="js-days"></tr>
    </thead>
    <tbody class="js-body"></tbody>
  </table>
</cinq-calendar>
```

The component upgrades automatically on `connectedCallback`.

## Examples

Interactive demos below cover single date, range, multiple dates, preselection,
a form, bounds, locale / week start, and an advanced `renderInner` events
calendar.

<CalendarPlayground />

### Single date

Default `mode="single"`. Add `deselect` to clear by clicking the selected day again.

```html
<cinq-calendar locale="fr" deselect name="arrival">
  <!-- header + table -->
</cinq-calendar>
```

### Date range

Set `mode="range"`. First click is the start, second is the end. Hover or
keyboard focus previews the range. A third click resets.

```html
<cinq-calendar locale="fr" mode="range" name="stay">
  <!-- header + table -->
</cinq-calendar>
```

### Multiple dates

Set `mode="multiple"`. Each click toggles a day in or out of the selection. No
range preview.

```html
<cinq-calendar locale="fr" mode="multiple" name="availability">
  <!-- header + table -->
</cinq-calendar>
```

The package does not enforce a maximum number of days. Cancel the change that
would go over yours:

```js
import { EVENTS } from "@agencecinq/utils";

const MAX = 3;

el.addEventListener(EVENTS.CALENDAR_BEFORE_CHANGE, event => {
  if (event.detail.values.length > MAX) event.preventDefault();
});
```

### Preselected dates

Seed the viewed month and selection from attributes:

```html
<cinq-calendar
  locale="fr"
  mode="range"
  data-month="10"
  data-year="2025"
  data-picked='["2025-11-10","2025-11-18"]'
>
  <!-- header + table -->
</cinq-calendar>
```

### Forms

`<cinq-calendar>` is a form-associated custom element. Inside a `<form>`, its
`name` is submitted with the picked days joined by commas (`2026-11-10`,
`2026-11-10,2026-11-14`). `required` blocks the submission until a day is
picked, or both ends of a range, with the browser's own message.
`form.reset()` brings back the `data-picked` selection, and `disabled` (or a
disabled `<fieldset>`) leaves the field out.

```html
<form>
  <p id="stay-label">Dates du séjour</p>
  <cinq-calendar name="stay" mode="range" required>
    <header>
      <!-- previous / next buttons -->
      <h2 class="js-title" id="stay-title" aria-live="polite"></h2>
    </header>
    <table role="grid" aria-labelledby="stay-label stay-title" aria-multiselectable="true">
      <thead>
        <tr class="js-days"></tr>
      </thead>
      <tbody class="js-body"></tbody>
    </table>
  </cinq-calendar>
  <button>Réserver</button>
</form>
```

Name the grid with `aria-labelledby`: a `<label for>` on the host does not
reach it.

### Bounds

`min` and `max` (`YYYY-MM-DD`) work as on `<input type="date">`: days outside
stay in the grid with `aria-disabled="true"` and cannot be picked. Without
them, every day can be picked. Both are observed, so a departure calendar can
follow the arrival:

```js
import { toDayString } from "@agencecinq/calendar";
import { EVENTS } from "@agencecinq/utils";

const today = toDayString(new Date());

arrival.setAttribute("min", today);
departure.setAttribute("min", today);

arrival.addEventListener(EVENTS.CALENDAR_CHANGE, ({ detail }) => {
  departure.setAttribute("min", detail.values[0] ?? today);
});
```

### Unavailable days

Set `aria-disabled="true"` on a day button in `renderInner`. Clicks, the
keyboard and the range preview already skip it. The **Advanced: event
markers** demo does this for days without events.

```js
const unavailable = ["2026-11-11", "2026-11-12"];

el.renderInner = inner => {
  const button = inner.querySelector(".js-day");

  if (unavailable.includes(button.dataset.day)) {
    button.setAttribute("aria-disabled", "true");
  }
};
el.render();
```

A range can still go over an unavailable day. Refuse it:

```js
el.addEventListener(EVENTS.CALENDAR_BEFORE_CHANGE, event => {
  const [start, end] = event.detail.values;

  if (end && unavailable.some(day => day > start && day < end)) {
    event.preventDefault();
  }
});
```

### Locale & week start

`locale` drives labels via `Intl`. Week start follows the locale. Override with
`first-day` (`0`=Sun ... `6`=Sat). Use the select in the playground to try
`en`, `fr`, `de`, `es`, `ja`, and `ar`.

```html
<!-- French to week starts Monday -->
<cinq-calendar locale="fr">...</cinq-calendar>

<!-- English labels, force Monday -->
<cinq-calendar locale="en" first-day="1">...</cinq-calendar>
```

Update at runtime:

```js
import { getWeekStart } from "@agencecinq/calendar";

const el = document.querySelector("cinq-calendar");
el.options.locale = "ja";
el.options.firstDay = getWeekStart("ja");
el.render();
```

### Cell hook

Override `renderInner` to enrich each day cell. Keep `.js-day` and `data-day`.
The playground **Advanced: event markers** example uses it to add `<time>`,
weekend styling, event dots, and to disable days without events.

```js
el.renderInner = (inner, date) => {
  const button = inner.querySelector(".js-day");
  if (!button) return;

  button.classList.add("MyDay");
  button.innerHTML = `<time datetime="${date.toISOString().slice(0, 10)}">${date.getDate()}</time>`;
};
```

## Required markup

| Selector | Required | Role |
| -------- | -------- | ---- |
| `<cinq-calendar>` | **Yes** | Host element |
| `.js-body` | **Yes** | Day cells container (`tbody`) |
| `.js-days` | **Yes** | Weekday headers row |
| `.js-previous` / `.js-next` | Optional | Month navigation |
| `.js-title` | Optional | Month / year label, filled by the calendar |
| `.js-day` | Generated | Day button |

## Selection state

The calendar writes the state on the cells it generates:

- `aria-selected="true"` on the `<td>` of each selected day, every day of a
  range included.
- The full date as `aria-label` on each day button (`lundi 16 novembre 2026`),
  `aria-current="date"` on today, and `aria-disabled="true"` on days that
  cannot be picked.
- Classes on the day button for styling: `active` (picked day, range ends),
  `range` (inside a range, ends included), `start` and `end`.

```css
td[aria-selected="true"] .js-day {
  background: #e5e7eb;
}

.js-day.active {
  background: #111827;
  color: #fff;
}
```

## Attributes

| Attribute | Description |
| --------- | ----------- |
| `locale` / `data-locale` | BCP 47 locale for labels |
| `mode` | `single` (default), `range`, or `multiple` |
| `deselect` | Allow clearing selection in `mode="single"` |
| `min` / `max` | First / last day that can be picked (`YYYY-MM-DD`). Observed |
| `name` | Form field name, also in the event details |
| `required` | Needs a day, or both ends of a range, to submit. Observed |
| `disabled` | Leaves the field out of the form and disables every day |
| `first-day` | Week start (`0`=Sun ... `6`=Sat) |
| `button-class` | Extra classes on day buttons |
| `data-month` / `data-year` | Initial view (`month` is `0`-`11`) |
| `data-picked` | JSON array of preselected `YYYY-MM-DD` days |

## Events

Dispatched on the host `<cinq-calendar>`.

| Event | Constant | Detail |
| ----- | -------- | ------ |
| `calendar:before-change` | `CALENDAR_BEFORE_CHANGE` | `{ values: string[], name?: string, waitUntil }` |
| `calendar:change` | `CALENDAR_CHANGE` | `{ values: string[], name?: string }` |

`calendar:before-change` comes first when a click or a key would change the
selection, with the selection to come in `values`. It does not bubble.
`preventDefault()` cancels the change, and `event.detail.waitUntil(promise)`
holds it until the promise settles (a rejection cancels it).
`calendar:change` bubbles once the selection has changed. `setPicked()` skips
`calendar:before-change`, and dispatches `calendar:change` unless `emit` is
`false`.

```js
import { EVENTS } from "@agencecinq/utils";

document.querySelector("cinq-calendar")?.addEventListener(
  EVENTS.CALENDAR_CHANGE,
  ({ detail }) => console.log(detail.values, detail.name),
);
```

## Keyboard

| Key | Action |
| --- | ------ |
| Arrow keys | Move by day / week |
| Home / End | First / last day of the week |
| Page Up / Page Down | Previous / next month |
| Shift + Page Up / Down | Previous / next year |
| Enter / Space | Select the focused day |

## API

| Method / property | Description |
| ----------------- | ----------- |
| `options` | Runtime options object |
| `picked` | Selected days as `YYYY-MM-DD` |
| `current` | Viewed `{ month, year, day }` |
| `render()` | Rebuild the grid |
| `setPicked(picked, emit?)` | Assign the selection, mirror `data-picked` and paint the grid. Emits `calendar:change` unless `emit` is `false` |
| `move(delta)` | Navigate by months (`-1` = previous, `1` = next) |
| `destroy()` | Detach listeners and clear the grid |
| `renderInner(inner, date)` | Per-cell hook (override) |

Exported helpers: `getWeekStart`, `toDayString`, `fromDayString`.
