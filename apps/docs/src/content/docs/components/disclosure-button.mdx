A disclosure button shows or hides a section of content. `<cinq-disclosure-button>`
wraps a trigger, wires up `aria-expanded` / `aria-controls`, toggles the visibility
of controlled regions, and dispatches open/close events.

Inspired by the
[WAI-ARIA Authoring Practices disclosure pattern](https://www.w3.org/WAI/ARIA/apg/patterns/disclosure/).

## Installation

```bash
pnpm add @agencecinq/disclosure-button
```

## Usage

```js
import '@agencecinq/disclosure-button';
```

```html
<cinq-disclosure-button>
  <button
    type="button"
    aria-expanded="false"
    aria-controls="details-1"
  >
    Show more
  </button>
</cinq-disclosure-button>

<div id="details-1" hidden>
  Disclosure content
</div>
```

Controlled regions live **outside** the component — typically as sibling elements
elsewhere in the document, referenced by `aria-controls`.

## Required markup

| Attribute / element | Required | Role |
| ------------------- | -------- | ---- |
| Inner `<button>` | **Yes** | Focusable trigger inside `<cinq-disclosure-button>`. |
| `aria-expanded` | **Yes** | Current disclosure state on the trigger. |
| `aria-controls` | **Yes** | Space-separated IDs of the controlled regions. |
| `hidden` | **Yes** | Set on each controlled region in its collapsed initial state. |

Use `[data-button]` instead of `<button>` when you need a different focusable
element as the trigger.

The component toggles the native `hidden` attribute on open/close. Layout is yours
— use CSS such as `.foo[hidden] { display: none; }` and `.foo { display: flex; }`.

## API

### Attributes

| Attribute | Required | Description |
| --------- | -------- | ----------- |
| `expanded` | No | Reflected state attribute on the host — useful for styling the wrapper. |

### Methods

| Method | Description |
| ------ | ----------- |
| `open(emit?)` | Opens the disclosure. Dispatches an event by default. |
| `close(emit?)` | Closes the disclosure. Dispatches an event by default. |
| `toggle()` | Toggles open/closed. Returns `false` if a cancelable event was aborted. |
| `destroy()` | Detaches listeners when removing the element from the DOM. |

### Properties

| Property | Description |
| -------- | ----------- |
| `button` | The inner trigger element. |
| `elements` | Controlled region elements resolved at connect time. |
| `expanded` | Whether the disclosure is currently open. |

## Keyboard & focus

The trigger must be a native focusable control — typically
`<button type="button">`. Enter and Space activate the button through browser
defaults; the component listens for `click`, which those keys dispatch on
buttons.

| Key | Function |
| --- | -------- |
| `Enter` | Toggle the disclosure (native button behavior). |
| `Space` | Toggle the disclosure (native button behavior). |

The component does **not** move focus into the controlled region on open, nor
restore focus on close. That matches the
[APG disclosure pattern](https://www.w3.org/WAI/ARIA/apg/patterns/disclosure/):
focus stays on the trigger. Once open, users can tab into focusable elements
inside the region if you include any.

While a region is collapsed, the `hidden` attribute keeps its content out of the
tab order and accessibility tree.

On `focus` / `blur`, a `.focus` class is toggled on the inner trigger so you can
style the focused state without relying solely on `:focus`:

```css
cinq-disclosure-button button.focus {
  outline: 2px solid currentColor;
  outline-offset: 2px;
}
```

## One button, multiple targets

`aria-controls` accepts a space-separated list of IDs. One disclosure opens or
closes **every listed region at once**:

```html
<cinq-disclosure-button>
  <button
    type="button"
    aria-expanded="false"
    aria-controls="verbal-component somatic-component material-component"
  >
    Show material components
  </button>
</cinq-disclosure-button>

<div id="verbal-component" hidden>…</div>
<div id="somatic-component" hidden>…</div>
<div id="material-component" hidden>…</div>
```

## Multiple buttons, one target

Several triggers can point to the **same** ID. Use one `<cinq-disclosure-button>`
per trigger — each instance listens for bubbling open/close events and syncs when
`event.detail.elements` references a shared DOM node:

```html
<cinq-disclosure-button>
  <button aria-expanded="false" aria-controls="lore-excerpt">Inspect glyph</button>
</cinq-disclosure-button>

<cinq-disclosure-button>
  <button aria-expanded="false" aria-controls="lore-excerpt">Read journal entry</button>
</cinq-disclosure-button>

<div id="lore-excerpt" hidden>…</div>
```

Events bubble. `aria-expanded` on each trigger reflects whether **all** of its own
controlled regions are visible.

## Events

| Event | Cancelable | Detail | Description |
| ----- | ---------- | ------ | ----------- |
| `disclosure-button:open` | Yes | `{ ids, elements, el }` | Fired on the inner trigger before the disclosure opens. Cancel to abort. |
| `disclosure-button:close` | Yes | `{ ids, elements, el }` | Fired on the inner trigger before the disclosure closes. Cancel to abort. |

```js
import { EVENTS } from "@agencecinq/utils";

$host.addEventListener(EVENTS.DISCLOSURE_BUTTON_OPEN, (event) => {
  console.log(event.detail.elements);
});
```

Both events bubble through `<cinq-disclosure-button>`. Call
`event.preventDefault()` to abort before the state changes:

```js
$host.addEventListener(EVENTS.DISCLOSURE_BUTTON_OPEN, (event) => {
  if (!userMayOpen()) {
    event.preventDefault();
  }
});
```

`event.detail` carries `{ ids, elements, el }` — `ids` are the raw
`aria-controls` tokens, `elements` the resolved DOM nodes, and `el` the trigger
that initiated the action.

## Updating the button label

The component does not change the trigger's visible text — that stays with the
consumer so copy, locale, and design stay under your control. Listen to the
open/close events and update the label yourself:

```js
import { EVENTS } from "@agencecinq/utils";

const labels = { closed: "Show details", open: "Hide details" };

$button.addEventListener(EVENTS.DISCLOSURE_BUTTON_OPEN, () => {
  $button.textContent = labels.open;
});

$button.addEventListener(EVENTS.DISCLOSURE_BUTTON_CLOSE, () => {
  $button.textContent = labels.closed;
});
```

## Read more / Read less

Keep a short excerpt in the document flow and put the rest in a hidden region. The
trigger is often styled as inline text rather than a prominent button:

```html
<article>
  <p>
    Nestled between the pines, La Cabane overlooks the lake — a timber lodge built
    for slow mornings and long dinners.
  </p>

  <div id="listing-details" hidden>
    <p>
      The main room opens onto a covered terrace with a wood-fired oven. Upstairs,
      four bedrooms share a single bathroom with a clawfoot tub.
    </p>
  </div>

  <cinq-disclosure-button>
    <button
      type="button"
      class="read-more"
      aria-expanded="false"
      aria-controls="listing-details"
    >
      Read more
    </button>
  </cinq-disclosure-button>
</article>
```

```js
import { EVENTS } from "@agencecinq/utils";

const labels = { closed: "Read more", open: "Read less" };

$button.addEventListener(EVENTS.DISCLOSURE_BUTTON_OPEN, () => {
  $button.textContent = labels.open;
});

$button.addEventListener(EVENTS.DISCLOSURE_BUTTON_CLOSE, () => {
  $button.textContent = labels.closed;
});
```

## Programmatic API

```js
const $host = document.querySelector('cinq-disclosure-button');

$host.open();
$host.close();
$host.toggle();
$host.destroy();
```

`open()` and `close()` accept an optional `emit` flag (default `true`). When
`true`, they dispatch `disclosure-button:open` / `disclosure-button:close`
before updating state — the same events as `toggle()`. Pass `false` to update
state silently.

Open from an external control:

```js
$openLink.addEventListener("click", () => {
  $host.open();
});
```

Close from a dismiss control inside the content:

```js
$dismissButton.addEventListener("click", () => {
  $host.close();
});
```

Use `close(false)` only when you intentionally skip the event and accept that
linked triggers will not sync.
